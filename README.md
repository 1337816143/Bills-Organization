# Bills Organization

一个 **local-first（本地优先）** 的个人账单整理网站，用于统一管理微信、支付宝和银行卡流水，并针对跨平台绑卡支付进行去重。

## 隐私设计

本仓库只保存网站代码，**不保存任何真实账单明细**。账单文件在浏览器端解析，交易记录、人工分类和去重关系默认只写入浏览器 IndexedDB，不上传到 GitHub 或其他服务器。

> 仓库是公开的，因此真实账单绝不作为静态资源提交到仓库。旧版 HTML 报告也可以在网页中本地迁移。

## 功能

- 多格式增量导入：CSV / TXT、XLS / XLSX、PDF、JSON、HTML。
- 已适配：微信支付、支付宝、中国建设银行、中国农业银行；其他表格尝试按通用字段自动识别。
- 自动提取账单明细和可识别的汇总信息。
- 相同账单重复导入时按稳定指纹跳过已有记录，仅增加新明细。
- 跨平台重复检测：优先保留微信 / 支付宝详细记录；高置信度银行卡镜像标记为 `confirmed-drop`；证据不足只标记 `suspected`，不会自动剔除。
- 每笔流水可手动归类：旅游支出、旅游期间非旅游支出、其他 / 非旅游、未判断。
- 自动计算：去重后支出、收入、净支出、纯旅游支出、旅游期间总支出。
- 多版本导出：仅支出、仅收入、收支汇总、旅游支出、旅游期间总支出、指定人工分类。
- 多格式导出：XLSX、CSV、JSON、独立 HTML 报告。
- 整库 JSON 备份 / 恢复。
- 支持从旧版账单分析 HTML 迁移 580 条历史流水，同时保留其完整原始字段、重复标记和系统旅游判断。

## 默认旅游口径

旅游开始日期默认为 `2026-08-08`，可在页面上修改。

- **纯旅游支出**：所有人工标记为“旅游支出”的净影响，包含出发前准备费用。
- **旅游期间总支出**：旅游开始日期之后，“旅游支出” + “旅游期间非旅游支出”的净影响。
- 退款 / 冲正按负数抵扣。
- 已确认的银行卡镜像重复记录保留展示，但不进入去重统计。

## 导入

浏览器端使用 SheetJS 解析 XLS / XLSX，使用 PDF.js 解析 PDF。支付宝 GBK/GB18030 CSV 会自动尝试编码识别。

导入后先做同来源稳定指纹去重，再做支付平台与银行卡之间的跨平台匹配。自动匹配综合日期、金额、支付渠道、银行卡尾号、时间差和商户文本；证据不足的记录只标“疑似重复”。

## 发布

仓库包含 GitHub Pages 工作流 `.github/workflows/pages.yml`，静态站点无需构建步骤。
